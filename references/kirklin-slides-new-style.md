# 增加新风格

## 适用场景

用户提供一套新的配图（图片、网页或幻灯片截图），并要求以后按此样式制作时，增加一种新风格。

新风格的底色、字体或整体效果需要与现有风格有明显区别。只更换一两种颜色时，修改项目中的 `style.css`，不新建风格。

## 命名规则

- 英文名使用小写英文单词和连字符，先写场合或特点，再写底色，例如 `launch-dark`、`report-light`。
- 中文名的格式为「X 风格」，例如「黑底发布会风格」。
- 名称中不包含品牌和产品名。

## 文件清单

新风格需要提交以下文件：

| 文件 | 说明 |
|-|-|
| `assets/styles/<英文名>/style.css` | 风格的样式，要求参见「style.css 的要求」。 |
| `assets/styles/<英文名>/pages/`（可选） | 某种版式在该风格中需要不同的结构时，放置同名页面替换共用的样例。 |
| `references/kirklin-slides-style-<英文名>.md` | 风格规范，章节与 `kirklin-slides-style-launch-dark.md` 相同，依次为适用场景、文件、画布和边距、颜色、字体和字号、基调和装饰、组件样式、各版式的尺寸、帖子截图。 |
| `SKILL.md` | 在风格列表中增加一行。 |

样例页位于 `assets/pages/`，由所有风格共用，新风格无需编写样例的文字。

## style.css 的要求

- 第一行为 `/* kirklin-slides style: <英文名> */`，项目复制该文件后通过这一行识别风格。
- 在 `:root` 中定义四个边距变量 `--safe-top`、`--safe-right`、`--safe-bottom`、`--safe-left`，检查脚本根据这四个变量判断文字是否超出版心。
- `html` 和 `body` 的尺寸为 1920×1080，超出部分隐藏，并设置背景色。
- 实现 [`kirklin-slides-components.md`](kirklin-slides-components.md) 中的全部类名和 `data-tone` 的五种基调，以及 [`kirklin-slides-layouts.md`](kirklin-slides-layouts.md) 中每种版式的布局。
- 光晕、色带等装饰绘制在 `.slide::before` 或 `.slide::after` 上。使用负的 `z-index` 时，需要为 `.slide` 添加 `isolation: isolate`，否则装饰会被背景遮挡。
- 由数据决定的长度和位置由页面以百分比定义，风格只控制容器的尺寸，因此更换风格时图表不会错位。
- 只使用系统自带的字体，不加载网络字体。
- 按 `assets/styles/launch-dark/style.css` 的章节顺序编写，只修改取值，不修改类名。

## 取值方法

- 颜色使用取色工具获取准确的值，按用途定义为变量，并注明每种颜色的含义。与现有风格含义相同的颜色（选用、原有、严重、警告）沿用相同的含义。
- 字号、行高、间距和圆角从样图中测量，按画布宽度 1920 换算为像素。
- 样图使用了系统中没有的字体时，选用系统中最接近的字体，并在风格规范中注明。
- 样图中的文字、数字、品牌标志、产品名和图片不放入仓库。

## 验证

1. 运行测试，确保全部通过。测试会检查每种风格 `style.css` 的第一行和替换页面，使用该风格渲染全部样例并核对尺寸，对每一页运行检查脚本，并生成汇总图。
   ```bash
   pnpm --dir <skill 目录> test
   ```
2. 生成该风格的汇总图，用 Read 工具逐张查看，并与用户提供的样图对照，确认颜色、字号和留白一致。
   ```bash
   node <skill 目录>/scripts/preview-style.ts <英文名> 汇总图.png
   ```
3. 将汇总图发给用户确认，用户确认后，新风格添加完成。
